## 흐름과 범위

`시작 → 습관 발견 → 내 계획 → 오늘의 실천 → 돌아보기 → 졸업`

- 일상 사용은 오늘 화면에서 실천 기록 한 번으로 끝난다.
- 돌아보기는 필요할 때 계획을 조정하는 경로다. 매일 강제로 거치지 않는다.
- 졸업은 본인의 선택이다. 기록은 보존하며 새로운 습관을 시작하거나 이전 습관을 다시 연습할 수 있다.
- Plus는 추가 동시 습관 또는 백업이 필요할 때만 선택한다. 무료 여정에 사용 기간 제한을 두지 않는다.
- 설정에서는 언어와 백업을 관리한다. 구매 복원은 유료 권한 복원이고, 기록 복원은 별도 백업 데이터 복원이다.

## 결제 구조

**현재 선택: iOS는 App Store 인앱 구매, Android는 Google Play 인앱 구매, 상품은 비소모성 일회성 Plus.** 나라별 PG나 자체 카드 결제 화면을 추가하지 않는다. 지역에서 허용되는 결제 수단은 해당 스토어의 구매창에 맡기며 특정 국가의 모든 결제 수단을 지원한다고 약속하지 않는다.

RevenueCat은 결제 대행 정산 주체를 대체하는 것이 아니라 스토어 구매 상태·권한 확인·복원을 통합하는 용도로 쓴다. entitlement는 `ssak_plus`, 현재 offering의 lifetime package로 연결한다. 각 플랫폼에 상품을 등록해야 하고 Android에서 구매를 소모 처리하지 않는다. [RevenueCat 비구독 구매 안내](https://www.revenuecat.com/docs/platform-resources/non-subscriptions).

- 신규 무료: 활성 습관 1개, 모든 힌트·실천·돌아보기·졸업 및 재시작.
- Plus: 최대 3개 동시 진행, 백업 및 복원.
- 기존 사용자: 기존 3개 슬롯 유지. 갱신·재구매를 요구하지 않는다.
- 가격은 앱 UI 언어나 GPS로 정하지 않는다. 스토어가 반환한 `priceString`을 그대로 표시한다.
- 정상 구매 응답만으로 해제하지 않고 `ssak_plus` 권한을 확인한다.
- 취소·실패·대기 상태에서는 새 권한을 임의로 부여하지 않는다. 다음 동기화에서 실제 승인 상태를 확인한다.
- 같은 스토어 계정에서 구매 복원. 기기 변경·재설치는 반드시 sandbox로 검증한다. [구매 복원](https://www.revenuecat.com/docs/getting-started/restoring-purchases).
- 현재 익명·무계정 구조에서는 iOS↔Android 구매 공유를 제공하지 않는다. 향후 공유를 제공하려면 구매자 식별·선택적 계정 설계가 필요하다. 단순 백업에 Pro 플래그를 넣는 방식으로 해결하지 않는다.
- 구매 복원으로 습관 기록까지 돌아오는 것은 아니다. 습관 데이터는 로컬 백업을 별도로 복원한다.

운영은 분기마다 실제 구매·환불·정산과 경쟁 상황을 검토하는 방식으로 시작한다. 사용자별로 다른 가격을 임의 제시하거나 UI 언어를 바꿔 가격이 달라지게 하지 않는다. 새 가격은 신규 구매에 적용하며 이미 구매한 일회성 권한을 없애지 않는다.

## 작은 수익이 남으려면

US$7.99 × (1 − 15%) ≈ $6.79는 수수료 하나만 뺀 예시다. 30%라면 약 $5.59다. 세금·환불·환전·SDK·계정 유지비·지원 시간은 별도이고 수수료 프로그램 자격도 확인해야 한다. 기존 [사업 판단서](renewal-review.ko.md)의 손익 시나리오와 함께 본다.

2026-10-04 조회 기준 RevenueCat 공개 요금은 월 추적 매출 $2,500까지 무료, 해당 수준에 도달하면 추적 매출의 1%를 안내한다. 적용 플랜과 MTR 계산은 실제 프로젝트에서 확인한다. 이는 스토어 수수료를 대체하지 않는다. [RevenueCat 가격](https://www.revenuecat.com/pricing/).

현재 Plus 가치가 경쟁 앱 대비 결제를 설득하는지는 미검증이다. 국가별 다운로드보다 `상품을 본 사람 → 정가 구매 → 환불 → 지원 시간 → 실제 정산액`을 확인한다. 초기 표본이 적으면 가격 A/B를 여러 나라에 동시에 벌이지 않고, 각 언어 사용자가 유료 이유를 이해하는지부터 검증한다.
