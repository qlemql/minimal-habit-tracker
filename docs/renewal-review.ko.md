# Ssak 리뉴얼: 판단, 제품, 검증 계획

작성일: 2026-10-04 · 작업 브랜치: `feat/ssak-renewal`

## 2.1 회고 개선 범위 — 2026-10-23 합의

상태: 로컬 앱 구현 및 웹 검증 완료(2026-10-23). 스토어 배포·실기기 검증 전.

목표는 **내 생활에 맞는 계획으로 조정하도록 돕는 것**이다. 기존 회고 화면을 활용하며, 매주 강제로 띄우는 팝업은 추가하지 않는다.

### 이번에 반영할 내용

- 주간 요약 한 개: 예시로 “지난주 5일 기록 · 평소 행동 2일, 작은 대안 3일”. 작은 대안도 실천한 날에 동일하게 포함한다. 예시 데이터는 레퍼런스에만 사용한다.
- 주요 선택 두 개: `이대로 이어가기` / `계획 바꾸기`.
- 계획 바꾸기를 선택하면 같은 화면에서 작은 대안, 실행 시점, 주간 목표 일수를 수정하고 저장한다. 취소하면 저장하지 않은 수정은 버린다.
- 계획 변경은 앞으로 적용하며 과거 실천 기록과 실천 종류는 유지한다. 새 목표로 과거 성공·실패를 다시 판정하지 않는다.
- 한국어와 영어를 함께 다듬는다. 영어 핵심 문구는 “Does this plan fit your life?”, 선택은 “Keep my plan” / “Adjust my plan”.
- 차트, 별도 통계 화면, 추가 완료 화면은 이번 범위에서 제외한다.

기존 `app/review.tsx`는 회고의 느낌·메모를 저장하고 조정 시 작은 대안만 수정했다. 2.1은 주요 선택을 두 개로 줄이고 작은 대안·실행 시점·주간 목표를 회고 이력과 함께 한 번에 저장하도록 확장했다. 새 회고에서는 메모 입력을 생략하며 기존 메모와 이력은 유지한다.

### 구현 결정

- 주간 집계는 기기 현지 날짜로 지난 완료된 월요일~일요일을 사용하며 연도를 포함한 실제 날짜 범위를 표시한다. 기록 없는 주에는 오늘의 작은 실천을 안내한다. 과거 기록에 실천 종류가 없으면 기존 의미대로 평소 행동으로 집계한다.
- 졸업은 회고 화면의 ‘습관 자세히’를 거쳐 기존 습관 상세 화면에서 접근한다. 기존 졸업·재시작 기능과 회고 이력·메모는 보존한다.
- 기본 주간 목표 선택은 기존 주 3/5/7일을 유지한다. 백업 등으로 다른 유효한 목표가 들어와 있으면 현재 값을 함께 표시해 편집만으로 바뀌지 않게 한다. 레퍼런스의 1–7일 선택을 그대로 확대 적용하지 않았다.
- 앱이 이미 지원하는 일본어·번체중국어에도 새 문구를 채워 누락 없이 제공한다. 한국어·영어 레퍼런스 검토를 원어민 감수 완료로 간주하지 않는다.

### 확인 기준

- 평소 행동과 작은 대안을 합한 실천 일수가 정확하며 같은 날짜는 중복 집계하지 않는다.
- 유지·변경·저장·취소가 동작하고 변경 뒤 과거 기록은 달라지지 않는다.
- 실제 앱의 네 언어와 작은 화면에서 문구·입력이 잘리거나 겹치지 않는다.
- 사용자가 요약을 보고 설명 없이 계획 유지 또는 조정으로 이어갈 수 있는지 확인한다.

레퍼런스: [한국어](../output/ssak-review-simple-reference.html), [영어](../output/ssak-review-english-reference.html). 앱 구현·배포 결과물이 아닌 검토용 화면이다.

검증: `npm run typecheck`, `npm run test:run`(12개 파일·92개 테스트), `npm run build` 통과. 회고에 연관된 E2E 14개 시나리오를 확인했다. 네 언어에서 저장·취소·유지·새로고침·졸업·재시작, 360/375/390px 화면을 검사했다. 기존에 숨겨진 화면도 같은 문구로 찾던 E2E 한 곳은 보이는 요소로 범위를 좁혀 재실행 통과했다. 실제 한국어 앱 화면도 브라우저에서 확인했다. 네이티브 실기기와 원어민 문구 감수는 남아 있다.

### 다음 후보 — 미확정, 2.1 범위에 자동 포함하지 않음

1. **쉬었다 돌아오는 경험 다듬기:** 기존 재시작·회고 안내를 먼저 확인하고, 며칠 비운 뒤에도 밀린 체크나 보충 기록 없이 오늘의 작은 대안으로 이어가기 쉬운지 살핀다. 기존 오늘 화면의 문구·행동을 우선 검토한다.
2. **작은 대안 예시 다듬기:** 기존 18개 아이디어를 바탕으로 읽기·걷기·기록 등에서 ‘바쁜 날에도 가능한 한 동작’이 바로 이해되는지 검토한다. 예시의 선택과 이해를 쉽게 만드는 데 집중한다.
3. **짧은 사용 관찰:** 초기 사용자에게 작은 대안 기록, 쉬었다 복귀, 계획 조정 세 과제를 주고 막히는 지점을 관찰한다. 각 후보를 실제 기능으로 만들지는 관찰 결과로 결정한다.

## 판단

시도할 가치는 있다. 다만 ‘광고 없는 미니멀 습관 앱’ 자체는 이미 경쟁이 치열하다. 수익성을 보장할 근거는 아직 없다. 이번 작업의 목표는 완전히 새로운 기능을 발명하는 것이 아니라 **습관 앱을 쓰다 멈춘 사람이, 더 작은 계획으로 다시 시작해 결국 기록 없이도 실천하게 되는 과정**을 일관되게 만드는 것이다.

주 타깃은 습관 자체에 관심 없는 사람이 아니다. 읽기·산책·기록 같은 작은 변화를 원하지만 큰 목표와 연속 기록 관리가 부담스러웠던 사람이다. 개발자가 지금 새 습관이 없어 앱을 쓰지 않는 것은 제품 실패의 증거로 보지 않는다. 졸업 뒤 사용 빈도가 줄어드는 것도 성공일 수 있다.

## 이번에 만든 제품

정원 성장·포인트·연속 성공 압박을 주 화면에서 제거했다. 계정과 자체 서버 없이 같은 React Native 앱으로 다음을 구현했다.

1. 실제로 원하는 습관 하나와 ‘이미 하는 일 다음에’라는 실천 계기를 정한다.
2. 바쁜 날에 할 수 있는 최소 행동과 주 3/5/7일 의도를 정한다.
3. 보통 실천과 작은 버전 실천을 모두 기록한다. 취소할 수 있고 빈 날은 실패로 표시하지 않는다.
4. 돌아보기에서 잘 맞는지 판단하고, 어렵다면 최소 행동을 바꾸며 이유를 남긴다.
5. 본인이 준비됐다고 판단하면 졸업한다. 기록은 남고 알림은 멈춘다. 필요하면 다시 연습한다.
6. 영어·한국어·일본어·번체중국어로 사용할 수 있다. 예시 여정은 명시적으로 표시하고 사용자가 선택했을 때만 생성한다.

차별점은 개별 기능의 독점이 아니라 **최소 행동 → 실제 경험 → 계획 수정 → 졸업**을 하나의 짧은 사용 경험으로 제공하는 조합이다. 이 조합을 사용자가 더 낫다고 느끼는지는 아직 검증하지 않았다.

## 광고 없는 수익 모델

- 신규 사용자: 활성 습관 1개, 실천·돌아보기·졸업을 기간 제한 없이 무료 제공한다. 졸업 후 다른 습관도 시작할 수 있다.
- Ssak Plus: 최대 3개 동시 진행과 로컬 백업·복원. 1회 결제다.
- 2026-10-06 결정: 무료 1개 / 구매 Plus 3개만 지원한다. 기존 사용자 예외는 제거하되 기록은 보존한다.
- 가격 가설: 미국 기준 $7.99. 실제 상품 가격은 스토어에서 받아 표시한다. 지금 상품을 등록하거나 결제 가격을 확정한 것은 아니다.

$7.99에서 수수료 15%만 가정하면 1건당 약 $6.79, 30%면 약 $5.59다. 세금·환불·SDK 비용·노동비는 제외한 금액이다. 프로그램 자격과 등록은 별도 확인해야 한다. [Apple 프로그램](https://developer.apple.com/app-store/small-business-program/), [Google 수수료 안내](https://support.google.com/googleplay/android-developer/answer/112622).

예를 들어 월 20건을 만들려면 설치 대비 구매율이 2%일 때 신규 설치 약 1,000건, 5%일 때 약 400건이 필요하다. **이는 예측이 아니라 필요한 유입 규모를 보여주는 산술 시나리오다.** 소액 수익이어도 발견 경로는 필요하다. 광고를 안 넣고 유료 광고를 안 집행하는 것과, 아무도 제품을 발견할 경로가 없는 것은 다른 운영 조건이다.

1회 결제는 구독 이탈 부담이 적지만 새 구매가 꾸준히 필요하다. 서버를 두지 않아 운영비를 줄였으며, 복잡한 콘텐츠·커뮤니티·AI를 넣지 않은 이유도 유지비 때문이다. 손익은 `실제 수령액 - 스토어/SDK/번역 등 현금 비용 - 유지보수 시간 비용`으로 본다.

‘계속 켜게 만드는 앱’보다 ‘다시 시도하는 데 도움이 되고, 가끔 다른 습관 때문에 돌아오는 도구’를 목표로 한다. 따라서 일일 접속률 하나로 제품의 성패를 판단하지 않는다.

## 실제 실행과 남은 경계

로컬 결과물은 `npm run build` 후 `npm run preview`로 실행하며 http://localhost:4173 에서 볼 수 있다. 웹의 데이터는 이 브라우저에 저장되고 네이티브 앱 데이터와 자동 동기화되지 않는다.

동작 테스트와 실행 방법은 [검증 기록](renewal-cycle.md)에 정리했다. 실제 스토어 상품·RevenueCat 프로젝트 키가 없으므로 이 빌드에서 결제 버튼은 비활성화된다. 무료 흐름은 끝까지 사용할 수 있다. 결제 성공을 가장하는 개발용 버튼은 없다.

스토어 공개, 실제 매출 검증, 원어민 감수, iOS/Android 실기기 알림·위젯 및 구매 복원 검증은 아직 실행하지 않았다. Windows에서 네이티브 JavaScript 번들은 생성했지만 설치 가능한 서명 앱을 만들고 기기에 설치한 것과는 다르다. 기존 위젯의 정원 표현·앱 이름·스토어 설명도 실제 2.0 공개 전에 함께 정리해야 한다.
